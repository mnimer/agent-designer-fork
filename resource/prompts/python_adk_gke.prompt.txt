### GKE AUTOPILOT & WORKLOAD IDENTITY ARCHITECTURE:
- GKE Autopilot clusters enforce Google Cloud best practices: automated node provisioning, autoscaling, and hardened security posture (`enable_autopilot = true` in `main.tf`).
- Workload Identity Federation binds the Kubernetes Service Account (`ksa-agent-workload`) in namespace `default` to a Google Cloud Service Account (`gsa-agent-workload@${PROJECT_ID}.iam.gserviceaccount.com`) via `roles/iam.workloadIdentityUser`.
- `k8s/deployment.yaml` specifies `serviceAccountName: ksa-agent-workload`. Pods authenticate to Vertex AI Gemini APIs seamlessly without mounted JSON credential keys.
- `server.py` implements `/health` (liveness) and `/ready` (readiness) HTTP probes returning `{"status": "ok"}` on port 8080.
- `Makefile` provides standardized targets:
  * `install`: Sets up Python virtual environment and installs dependencies
  * `dev`: Runs `uvicorn server:app --reload --port 8080` locally
  * `test`: Runs `pytest test_agent.py`
  * `infra`: Runs `terraform init && terraform apply -auto-approve`
  * `deploy`: Runs `adk deploy gke --project=$(PROJECT_ID) --cluster=$(CLUSTER_NAME) --location=$(REGION) --namespace=$(NAMESPACE)` or `kubectl apply -f k8s/`
